# GenTest Bug Report - Critical Parser Validation Issue

**Date**: 2025-08-30  
**Severity**: High  
**Impact**: Blocks generator testing for all state machines  
**Reporter**: Client via development team  
**Investigator**: Development Team  

---

## Executive Summary

GenTest tool fails to generate code for valid state machine definitions due to incorrect attribute argument validation. The parser reports FSM004 warning claiming the `[StateMachine]` attribute lacks required arguments, even when both arguments are properly provided. This creates an inconsistency where the discovery phase marks machines as VALID while the parser fails validation.

---

## Issue Description

### Problem Statement
When running GenTest on any state machine with correct `[StateMachine(typeof(StateEnum), typeof(TriggerEnum))]` attribute, the generator:
1. Reports warning FSM004: "The [StateMachine] attribute requires at least two arguments"
2. Fails parser validation 
3. Does not generate any state machine code
4. Shows inconsistent status (VALID in discovery, failed in parser)

### Business Impact
- **Development blocked**: Cannot test generator changes using GenTest
- **CI/CD affected**: Automated testing of generators impossible
- **False positives**: Valid code reported as invalid
- **Developer confusion**: Inconsistent error messages

## Root Cause Analysis

### Technical Investigation

1. **Attribute Resolution Failure**
   ```csharp
   // In StateMachineParser.cs
   var fsmAttribute = classSymbol.GetAttributes()
       .FirstOrDefault(a => a.AttributeClass?.ToDisplayString() == StateMachineAttributeFullName);
   
   var ctorArgCount = fsmAttribute?.ConstructorArguments.Length ?? 0;  // Returns 0 instead of 2!
   ```

2. **Compilation Context Issue**
   - GenTest creates a minimal Roslyn compilation
   - Adds `Abstractions.dll` as MetadataReference
   - But semantic model cannot fully resolve attribute constructor parameters
   - `ConstructorArguments.Length` returns 0 even with valid `typeof()` arguments

3. **Validation Flow**
   ```
   User Code: [StateMachine(typeof(HState), typeof(HTrigger))]
        ↓
   Discovery: Matches attribute by name → VALID ✓
        ↓
   Parser: Reads ConstructorArguments.Length → 0 (WRONG!)
        ↓
   Validation: ctorArgCount < 2 → FSM004 Warning
        ↓
   Result: Parser validation failed, no code generated
   ```

### Why This Happens

The issue occurs because:
1. **Limited Compilation Context**: GenTest builds a minimal compilation for speed
2. **Metadata Resolution**: Roslyn's semantic model can't fully resolve generic attribute arguments
3. **Validation Logic**: Parser relies on `ConstructorArguments.Length` which fails in this context
4. **No Fallback**: Parser doesn't check syntax tree when semantic model fails

## Proposed Solutions

### Solution 1: Fix Parser Validation (Recommended)
**Location**: `Generator/Parsers/StateMachineParser.cs`

```csharp
// Current problematic code:
var ctorArgCount = fsmAttribute?.ConstructorArguments.Length ?? 0;

// Proposed fix:
var ctorArgCount = fsmAttribute?.ConstructorArguments.Length ?? 0;
if (ctorArgCount == 0 && fsmAttribute != null)
{
    // Fallback: Check syntax tree when semantic model fails
    var attrSyntax = classDeclaration.AttributeLists
        .SelectMany(al => al.Attributes)
        .FirstOrDefault(a => /* match StateMachine */);
    
    if (attrSyntax?.ArgumentList?.Arguments.Count >= 2)
    {
        ctorArgCount = attrSyntax.ArgumentList.Arguments.Count;
    }
}
```

### Solution 2: Improve GenTest Compilation
**Location**: `GenTest/Program.cs`

```csharp
// Add more comprehensive references for better resolution
private static CSharpCompilation BuildCompilation(string inputPath)
{
    // ... existing code ...
    
    // Add System.Runtime for better type resolution
    refs.Add(MetadataReference.CreateFromFile(
        typeof(Type).Assembly.Location));
    
    // Use higher language version for better attribute support
    var parseOptions = new CSharpParseOptions(
        LanguageVersion.Latest,
        DocumentationMode.Parse);
}
```

### Solution 3: Skip Validation in Test Context
**Location**: `Generator.Rules/Rules/MissingStateMachineAttributeRule.cs`

```csharp
public IEnumerable<ValidationResult> Validate(MissingStateMachineAttributeValidationContext context)
{
    // Skip validation if in test/limited context
    if (context.IsTestContext && context.HasStateMachineAttribute)
    {
        yield return ValidationResult.Success();
        yield break;
    }
    
    // ... existing validation ...
}
```

### For Developers Testing Generators

1. **Use Full Project Build** instead of GenTest:

   ```bash
   dotnet add package FastFsm
   # Add test file and build normally
   ```

2. **Ignore FSM004 in GenTest** output:
   - If you see FSM004 but your attribute is correct, ignore it
   - This is a GenTest issue, not your code issue

3. **Modify Local Generator** (not recommended for production):
   - Temporarily comment out argument count validation
   - Remember to restore before committing
